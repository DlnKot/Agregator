# Alfa Remote Client Roadmap

Последнее обновление: 2026-03-18

## Цель

Alfa Remote Client (ARC) - единая оболочка для запуска корпоративных клиентов удаленного доступа (RDP, VMware Horizon, Citrix) и вспомогательных утилит (VPN), с удобным управлением подключениями и безопасной установкой обновлений.

## Что уже сделано

### Продукт и UI

- [x] Управление подключениями (создание, редактирование, удаление).
- [x] Разделы "Подключения" и "Настройки".
- [x] Вкладка "Проверка сети" (ping сервисов + сведения о стране/провайдере).
- [x] Настройка порога задержки для проверки сети (мс).
- [x] Фильтрация по типу клиента (All/RDP/Horizon/Citrix).
- [x] Фиксация лэйаута под размер окна Electron (sidebar/main растягиваются по окну, контент скроллится внутри).
- [x] Переключение светлой/темной темы + сохранение выбора в `localStorage` (`arc_theme`).
- [x] Глобальная система CSS-переменных (light/dark) + `color-scheme`.
- [x] Встроенный шрифт Styrene A через `@font-face` (одинаковый вид на всех ОС).
- [x] Исправления контрастности кнопок/инпутов для тем (включая `FirstRunModal` и секцию обновления).
- [x] Раздел "Помощь" с информацией о:
  - HelpDesk (контакты поддержки, как создать обращение)
  - Indeed (инструкция по регистрации и получению кода)
  - Виды удалённых рабочих мест (VDI, ПУРМС, CITRIX, VPN, Jira/Confluence)
  - Чат-бот IT Helps (как пользоваться и возможности)

### Лаунчеры клиентов

- [x] RDP (Windows): запуск через `mstsc.exe` и генерация `.rdp`.
- [x] RDP (macOS): приоритетно через bundle id `com.microsoft.rdc.macos` (Windows App), fallback - системный handler `.rdp`.
- [x] VMware Horizon: удален `domainName` из параметров запуска, username нормализуется (DOMAIN\\user -> user).
- [x] VMware Horizon (Windows): определение пути к клиенту через реестр `HKLM\\SOFTWARE\\VMware, Inc.\\VMware VDM` (`ClientInstallPath`) + fallback на поиск по дефолтным путям.
- [x] Citrix (macOS): не открываем StoreFront URL в браузере; запускаем Citrix Workspace.
- [x] Citrix (macOS): авто-регистрация StoreFront через `citrixreceiver://createaccount` при отсутствии аккаунта в `~/Library/Application Support/Citrix/Receiver/Accounts/`.
- [x] Citrix: StoreFront берется из карточки подключения (`connection.storeUrl`), настройки - fallback; `/discovery` нормализуется.
- [x] VPN (macOS): запуск "Endpoint Security VPN" через `open -a`.
- [x] VPN (Windows): запуск `TrGUI.exe` (учтен дефолтный путь `C:\\Program Files (x86)\\CheckPoint\\Endpoint Connect\\TrGUI.exe`).

### Стабильность и качество

- [x] Обработчики `child.on('error')` для `spawn(...)` в лаунчерах (защита от падений при ENOENT).
- [x] Улучшения автоапдейтера на macOS: `quitAndInstall(false, true)` + fallback `app.relaunch()/app.exit()` если нет перезапуска.
- [x] Диагностика code-signing на macOS в логах (подсказка причины "скачалось, но не установилось").

### Release/CI

- [x] GitHub Actions workflow сборки Windows/macOS и публикации релиза.
- [x] Генерация/прикладывание `latest.yml` и `latest-mac.yml` + `*.blockmap`.
- [x] Исправление рассинхрона имен macOS артефактов и `latest-mac.yml` (скрипт `scripts/sync-mac-artifact-names.js`).

## Что стоит сделать дальше (приоритетно)

### Автообновления на macOS (блокер для продакшена)

- [ ] Включить code signing и notarization для macOS сборок в CI (сертификаты, entitlements, hardened runtime).
- [ ] Прописать явную проверку/сообщение пользователю в UI: "Автообновления на macOS требуют подписанную сборку", если подписи нет.
- [ ] Протестировать сценарии arm64/x64 + Rosetta (выбор правильного `*-mac.zip`).

### UI/UX

- [ ] Иконка приложения (mac `.icns`, win `.ico`) + единый бренд-пак.
- [ ] Поиск по подключениям (по имени/хосту/описанию).
- [ ] Сортировка и избранное (пины).
- [ ] Профили подключений (UI): создание, переключение профиля, быстрый запуск набора.
- [ ] Импорт/экспорт подключений (JSON) и миграции схемы.

### Клиенты и интеграции

- [ ] Citrix macOS: более точная проверка "аккаунт уже зарегистрирован" (не best-effort поиск строк, а чтение структуры аккаунта).
- [ ] Citrix: запуск конкретного ресурса на macOS (если Citrix Workspace поддерживает CLI/URL scheme для launch).
- [ ] VPN: настройка пути/выбора VPN клиента в UI (на случай нестандартных установок).

### Безопасность и надежность

- [ ] Безопасное хранение учетных данных (Keychain on macOS, Credential Manager on Windows) вместо хранения в plain конфиге.
- [ ] Централизованный error reporting (лог + понятные сообщения в UI), не только `app.log`.
- [ ] Набор автотестов минимум: unit для нормализации настроек/URL, smoke для IPC контрактов.

## Идеи на потом

- [ ] Трей/менюбар режим, автозапуск, быстрый запуск из трей-меню.
- [ ] Роли/политики: deployment-defaults с возможностью запрета редактирования отдельных полей.
- [ ] Телеметрия без персональных данных (опционально) для качества обновлений/крашей.
- [ ] i18n (RU/EN) и нормализация копирайта/терминов.

## Примечания

- Roadmap живой: пункты добавляются по фидбеку и по реальным ограничениям клиентов (Citrix/Horizon/VPN).
- Для macOS auto-update ключевое: подпись и notarization, иначе обновление может скачиваться, но не применяться.
